SourceManager 完整文档

sm 是一个用 C# / .NET 10 实现的下一代版本控制系统。它采用 SHA-256 内容寻址存储、对象化的提交历史、分支/标签/变基/贮藏等工作流，并提供基于 JSON 的远程传输与内置服务器。

.NET 10 · C# 13 SHA-256 内容寻址 44 个命令 JSON 机器可读输出 原生 sm:// 协议 二进制帧 + 握手 file / HTTP / SSH 兼容 版本 1.0.0

概述 #

SourceManager（命令行名为 sm）是一个自包含的分布式版本控制系统，提供提交、分支、合并、变基、贮藏、标签与远程协作等完整工作流，并采用自有协议与简洁一致的对象模型。

内容寻址存储

每个对象以 SHA-256 摘要命名，松散对象使用 zlib 压缩存放在 .sm/objects/ 下。

完整工作流

暂存、提交、分支、合并、变基、拣选、回退、贮藏、重置、二分查找一应俱全。

机器可读输出

15 个命令支持 --json，输出带版本信封的结构化文档，便于脚本与 CI 集成。

内置协作能力

sm serve 提供自有 sm:// 协议服务端（二进制帧），并保留 HTTP/stdio 作为兼容承载。

设计要点

  • 单一入口：所有命令注册在 Program.cs 的根解析器中，统一处理别名、全局选项与帮助。
  • 规范化编码：对象的提交/标签负载强制使用 LF 换行，因为换行符也会参与哈希计算。
  • 读写分离的引用存储：分支、标签、远程跟踪引用分别落在 refs/heads、refs/tags、refs/remotes 下，另有 logs/ 记录 reflog。
  • 自有传输协议：sm:// 在 TCP 上使用二进制帧与版本握手；对象以“未压缩负载 + Base64”的 JSON 负载传输。
命名说明：本文中 sm 指 SourceManager 可执行文件；.sm 指非裸仓库的元数据目录。示例命令默认在仓库工作树内执行。

安装与构建 #

项目为单个 .NET SDK 项目（SourceManager.csproj），目标框架 net10.0，程序集名为 sm，依赖 System.IO.Hashing 9.0.0。

前置条件

  • .NET SDK 10.0 或更高版本（开发环境使用 10.0.302）。

构建

# 在项目根目录
dotnet build

# 运行（通过 SDK）
dotnet run -- status

# 发布单文件可执行程序（win-x64）
dotnet publish -c Release

构建产物默认位于 bin/Debug/net10.0/win-x64/sm.exe。项目已配置 PublishSingleFile=true、SelfContained=false、RuntimeIdentifier=win-x64。

验证安装

sm version
# sm version 1.0.0

sm --help
提示：任意命令都可使用 --help 查看该命令的用法，例如 sm log --help。

快速开始 #

下面演示一个完整的最小工作流：初始化、暂存、提交、查看历史、创建分支、合并。

# 1. 初始化一个新的仓库（默认分支 main）
sm init myproject
cd myproject

# 2. 创建内容并暂存
echo "hello" > README.md
sm add README.md

# 3. 查看状态（可加 --short 或 --json）
sm status
sm status --short

# 4. 提交
sm commit -m "first commit"

# 5. 查看历史
sm log --oneline --graph

# 6. 创建并切换到功能分支
sm switch -c feature/login

# 7. 在分支上修改并提交
echo "login" > login.txt
sm add login.txt
sm commit -m "add login"

# 8. 切回主分支并合并
sm switch main
sm merge feature/login

# 9. 查看提交图与引用
sm log --oneline --decorate --all

与远程协作

# 添加远程（自有协议 sm://；兼容 file://、http(s)://、ssh://）
sm remote add origin sm://host:9418/

# 携带令牌：sm://token@host:9418/

# 首次推送并设置上游
sm push -u origin main

# 之后拉取更新
sm pull origin main
说明：默认承载是自有 sm:// 协议。兼容承载仍需以 file://、http://、https:// 或 ssh:// 开头。scp 风格 user@host:path 不被支持。

核心概念 #

三棵树：工作树、索引、HEAD

区域含义相关命令
工作树 (working tree)你实际编辑的文件目录。add、status、restore、checkout
索引 (index / 暂存区)下一次提交将要记录的快照，存放于 .sm/index。add、rm、reset、ls-files
HEAD当前检出的提交；通常通过符号引用指向某个分支。checkout、switch、reset、rev-parse

对象模型

仓库中的所有内容都保存为四类对象，以 SHA-256 摘要作为唯一标识（64 位十六进制字符串）：

类型用途
blob文件内容（原始字节，不做行尾转换）。
tree目录：以名字字典序排列的条目（模式、名字、子对象 ID）。
commit快照：指向一个 tree、零或多父提交、作者/提交者签名与消息。
tag附注标签：指向某对象、类型、标签名、打标签者与消息。

引用 (refs)

  • HEAD：ref: refs/heads/<branch> 表示在分支上；直接是 64 位哈希表示“分离 HEAD”。
  • 分支：refs/heads/<name>，内容为一个提交哈希。
  • 标签：refs/tags/<name>，轻量标签直接指向提交，附注标签指向 tag 对象。
  • 远程跟踪分支：refs/remotes/<remote>/<branch>。
  • reflog：logs/ 下按引用路径记录引用移动历史，用于恢复与 HEAD@{n} 语法。

冲突与合并状态

合并、变基、拣选、回退等操作会写入状态文件（如 .sm/MERGE_HEAD、.sm/CHERRY_PICK_HEAD、.sm/CONFLICTS）。发生冲突时对应命令返回非零退出码，工作树中写入冲突标记，需解决后重新 add 并提交（或使用 --continue / --abort）。

修订语法 #

所有接受修订参数的命令都使用统一的解析器。语法如下：

<rev>   := <base> ( '~' [n] | '^' [n] )*
<base>  := HEAD
         | HEAD@{<selector>}
         | <branch>
         | <tag>
         | <remote>/<branch>
         | <4..64 位十六进制前缀>
<revpath> := <rev> ':' ['/']<path>
写法含义
HEAD当前提交。
HEAD~3沿第一父提交向上 3 代（~ 省略数字时为 1）。
HEAD^2第 2 个父提交（合并提交的第二个父）。^0 表示自身（剥离标签）。
main、v1.0、origin/main分支、标签、远程跟踪分支（标签会被剥离到其提交）。
1a2b3c4d对象 ID 前缀（至少 4 位）。
HEAD@{2}HEAD reflog 中的第 N 条（0 为最近）。
HEAD~2^2操作符可链式组合。
main:src/app.cs提交树中路径对应的 blob。
比较两个修订：分别作为参数传入即可，例如 sm diff main feature。

日期格式 #

供 log --since/--until、shortlog --since、gc --prune、reflog --expire 等使用。

形式示例
当前时间now
相对时间2.weeks.ago、3.days.ago、10.minutes.ago、1.month.ago、1.year.ago
绝对时间任何 DateTimeOffset.TryParse 可解析的字符串，如 2026-09-24、2026-09-24T13:05:00+08:00

相对时间的单位：second、minute、hour、day、week、month（按 30 天）、year（按 365 天），可带复数 s。无法解析的值会被当作“无过滤条件”。

忽略规则 #

忽略规则按从低到高的优先级加载，靠后者覆盖前者：

  1. 全局排除文件：环境变量 SM_GLOBAL_EXCLUDES 指定，或默认 ~/.sm/ignore；
  2. <root>/info/exclude；
  3. <root>/.sm/info/exclude（sm init 会创建，内容为注释行）；
  4. 仓库根下的 .smignore；
  5. 各级子目录中的 .smignore（按路径顺序）。

规则支持 ! 取反。目录遍历会自动跳过 .sm、.git、.svn。

钩子 #

在 <sm-dir>/hooks/ 中放置脚本即可挂接工作流。钩子以工作树为当前目录运行，返回非零退出码可中止对应操作。

钩子参数触发与语义
pre-commit无提交前运行；非零退出中止提交（--no-verify 可跳过）。
commit-msg消息文件路径可原地改写提交消息；非零退出中止提交。
post-commit无提交记录后运行；失败只警告。
pre-merge被合并的分支名合并前运行；非零退出中止合并。
post-merge已合并的分支名合并成功后运行；失败只警告。
pre-push远程名、URL推送前运行；非零退出中止推送（--no-verify 可跳过）。

钩子文件可以是裸名（如 pre-commit），也可带扩展名以选择解释器：.cmd/.bat、.ps1、.sh/.bash、.py、.js、.exe；带 #! shebang 的脚本按其声明的解释器运行。设置 SM_NO_HOOKS=1 可全局禁用钩子。

JSON 输出 #

在支持的命令后添加 --json（或 --format json，大小写不敏感）即可获得机器可读输出。成功文档使用固定信封：

{
  "sm": 1,
  "command": "<命令名>",
  "data": { ... }
}

JSON 输出到标准输出，缩进为 2 空格，非 ASCII 字符不转义。时间戳格式为 yyyy-MM-ddTHH:mm:sszzz。

支持 JSON 的命令（15 个）

status、log、diff、show、describe、rev-parse、shortlog、clean、cat-file、hash-object、ls-tree、ls-files、merge-base、tag（列表模式）、verify。

示例：sm status --json

{
  "sm": 1,
  "command": "status",
  "data": {
    "branch": "main",
    "upstream": "origin/main",
    "ahead": 1,
    "behind": 0,
    "detached": false,
    "clean": false,
    "staged": [ { "path": "a.txt", "oldPath": null, "status": "added" } ],
    "unstaged": [],
    "untracked": [ "b.txt" ],
    "conflicted": []
  }
}

状态码取值

文件状态用字符串表示：added、modified、deleted、renamed、copied、type_changed、unmerged、untracked、ignored。

说明：成功时输出 data 信封；命令失败且请求了 JSON 时输出 error 信封（含 code：usage、unknown-command、error 或 fatal）。同一次运行只输出一个信封，诊断文本仍同时写入标准错误。

退出码与输出约定 #

退出码含义
0成功；也用于 --help、无参数（根帮助）、--version、谓词为真。
1一般失败、用法错误、命令错误；也是谓词的“假”信号（如 merge-base --is-ancestor、cat-file --exists）。
128致命错误：Program.Main 中所有未捕获异常，以及 init 的失败。

输出流约定

  • 成功的数据与散文输出 -> 标准输出（stdout）。
  • 诊断信息（error:、fatal:、hint:）-> 标准错误（stderr）。
  • warning: … 由 Terminal.WriteWarning 添加前缀并写入标准输出。
  • 颜色在标准输出被重定向时自动关闭。

参数解析规则

  • 长选项支持 --name value 与 --name=value；布尔选项忽略附带的值。
  • 短选项可合并（如 -am）；非布尔短选项必须位于合并串末尾并紧跟其值，且值不能直接粘连。
  • -- 之后的所有参数进入透传列表；restore/switch 之外的命令只读取位置参数。
  • 选项名与命令名均大小写不敏感。未知选项会产生 error: Unknown option: --x 并以退出码 1 结束。

对象格式 #

哈希与松散对象

  • 算法：SHA-256，32 字节摘要，64 位小写十六进制。
  • 对象 ID 计算方式：SHA256("<type> <len>\0<payload>")，类型为 blob/tree/commit/tag。
  • 磁盘存储：在帧化负载外再套一层 zlib 压缩，路径为 objects/<hex[0:2]>/<hex[2:]>。
  • 相同内容自动去重（已存在则跳过写入）。

Tree

每个条目: "<mode> <name>\0" + 32 字节原始哈希
条目按 name 的字典序排列

模式使用补零的 6 位十进制（例如普通文件 033188）；显示时通过 FileModeFormat.ToOctal 呈现为八进制 100644。文件模式值：普通 33188、可执行 33261、符号链接 40960、目录 16384、子模块 57344。

Commit

tree <64hex>
parent <64hex>            （0 个或多个）
author <name> <email> <unix秒> <±HHMM>
committer <name> <email> <unix秒> <±HHMM>
<额外头> <值>            （0 个或多个）

<消息>

负载强制使用 LF 换行（换行符参与哈希，因此必须规范化）。

Tag（附注标签）

object <64hex>
type <blob|tree|commit|tag>
tag <name>
tagger <name> <email> <unix秒> <±HHMM>

<消息>

Reflog 行格式

<old64hex> <new64hex> <name> <email> <unix秒> <±HHMM>\t<message>\n

索引文件

  • 12 字节头：ASCII DIRC、int32 小端版本 2、int32 小端条目数。
  • 每条目固定字段 78 字节，后跟 UTF-8 路径与 NUL 填充到 8 字节边界。
  • 文件末尾附加 32 字节 SHA-256 校验和，Load 时校验；损坏或外部改动的索引会被拒绝。
  • 条目按路径字典序排列，通过临时文件 + 原子移动保存。

锁

LockFile 以 CreateNew 独占方式获取锁，写入进程 ID 与机器名，轮询退避（初始 50ms，上限 500ms，默认超时 3 秒）。超过 5 分钟的陈旧锁会被自动打破。仓库级锁文件为 .sm/sm.lock。

远程协议与服务器 #

传输方案

sm 的默认传输是自有协议 sm://：在 TCP 之上使用自定义二进制帧与握手。HTTP/HTTPS 与 SSH 保留为兼容承载（通过 sm serve --http / --stdio 启用），不再是默认方式。

方案实现默认说明
sm://SmTcpTransport是原生二进制帧协议，TCP 端口默认 9418。
file://FileTransport—直接访问本地仓库目录。
http:// / https://HttpTransport—兼容承载：JSON over HTTP，Bearer Token 认证。
ssh://SshTransport—兼容承载：通过系统 ssh 运行远程 sm serve --stdio。

URL 必须以带 :// 的方案开头。scp 风格 user@host:path 不被支持。

原生 sm:// 帧格式

每条消息是一个固定 12 字节头部 + 变长负载的二进制帧：

+--------+---------+-------+-------+-------------------+
| magic  | version | type  | flags | payload length    |
| 4 字节 | 1 字节  | 1 字节| 2 字节| 4 字节（大端）    |
+--------+---------+-------+-------+-------------------+
| payload: UTF-8 JSON，length 字节                      |
+------------------------------------------------------+

magic = ASCII "SMP1"   frame version = 1   flags 保留（0）

帧类型：1 Hello、2 HelloAck、3 Request、4 Response、5 Error、6 Bye、7 Ping、8 Pong。负载沿用同一套 JSON 方法语义，因此服务端只有一份方法派发表。

握手与协商

  1. 客户端建立 TCP 连接后发送 Hello 帧：{"protocol":"sm","version":"1.0","frameVersion":1,"capabilities":[...],"token":"..."}。
  2. 服务端校验主版本（必须为 1）、帧版本与可选令牌，成功则回 HelloAck（含 protocol、version、frameVersion 与能力列表），失败回 Error 帧并关闭连接。
  3. 此后每个 Request 帧携带数字 id，服务端在 Response 中回显；Ping/Pong 用于保活，Bye 用于优雅关闭。

协议标识为 sm/1.0（主版本 1 必须匹配），二进制帧版本为 1，两者独立演进。对象在负载中同样以“未压缩负载 + Base64”传输：

{"hash":"<64hex>","type":"Blob|Tree|Commit|Tag","data":"<base64>"}

认证

场景机制
sm:// 客户端URL user-info（sm://token@host/）> SM_TOKEN_<REMOTE> > SM_TOKEN，随 Hello 帧发送。
sm:// 服务端SM_SERVE_TOKEN；长度检查 + 恒定时间比较，未设置则不认证。
HTTP 客户端URL 内嵌令牌 > SM_TOKEN_<REMOTE> > SM_TOKEN，作为 Authorization: Bearer。
HTTP 服务端SM_SERVE_TOKEN；使用长度检查 + 恒定时间比较。
SSH由系统 ssh 处理密钥/代理；PasswordAuthentication=no、StrictHostKeyChecking=accept-new。

服务器示例

# 启动原生 sm:// 协议服务（默认）
sm serve --path /srv/repo --port 9418 --bind +

# 可选：兼容承载
sm serve --path /srv/repo --http      # HTTP
sm serve --path /srv/repo --stdio     # stdio（供 SSH 使用）

# 要求认证
#   Windows:  $env:SM_SERVE_TOKEN = "secret"
#   Linux:    export SM_SERVE_TOKEN=secret

# 添加远程并推送
sm remote add origin sm://host:9418/
sm push -u origin main
# 携带令牌：sm://token@host:9418/
安全：原生 sm:// 与 HTTP 均为明文传输、未内置 TLS 加密，且每进程只服务一个仓库。绑定非回环地址前请务必设置 SM_SERVE_TOKEN。可在前面放置反向代理或 VPN 来提供加密。

架构与执行流程 #

代码组织为若干职责清晰的模块（均为命名空间 SourceManager）：

模块职责
Program / ArgumentParser命令注册、全局选项、解析与分发、帮助。
Repository仓库发现、初始化、检出、打开、索引/对象/引用/合并门面。
ObjectStore松散对象的读写、哈希、数据统计、GC 辅助。
RefStoreHEAD、分支、标签、远程引用、reflog 与各类状态文件。
Index暂存区的加载/保存与条目管理。
DiffEngine / MergeEngine差异计算（Myers/Patience/Histogram）与三方合并。
RevisionResolver修订语法解析。
Transport 系列 + SmServer + SmWireProtocolsm:// 原生协议、file/http/ssh 传输与 HTTP/stdio/TCP 服务器。
ConflictState / Autostash / RebasePlan进行中操作的状态持久化。
JsonOut机器可读输出的信封与辅助。

一次命令调用的流程

  1. Main 构建根解析器（注册别名、全局选项与所有命令）。
  2. 解析参数：命中命令则把剩余参数交给该命令的子解析器；否则处理 --version/帮助/未知命令。
  3. 解析错误逐条以 error: 输出并返回 1。
  4. 调用命令处理器的 Execute(ParseResult)，在仓库上下文（Repository.Find 向上查找）中执行。
  5. 未捕获异常统一转为 fatal: <message> 并返回 128。
